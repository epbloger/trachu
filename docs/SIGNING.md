# Постоянная подпись релиза

В публичной CI-сборке нет ключа издателя. Debug APK подписан отладочным ключом; release APK и AAB по умолчанию не подписаны. Не публикуйте их как коммерческую сборку.

## Действия владельца

1. Если ключ ТРАЧУ. уже существует, используйте именно его. Иначе создайте отдельный постоянный ключ через Android Studio → Generate Signed Bundle / APK → Create new. Храните JKS вне D:\NP и вне репозиториев. Сделайте защищённую резервную копию; утрата ключа может сделать обновления невозможными. Для Google Play учитывайте правила Play App Signing и upload key; для RuStore сохраняйте совместимый ключ обновления.
2. В доверенном локальном окружении задайте переменные процесса `TRACHU_SIGNING_ENABLED=true`, `TRACHU_KEYSTORE_PATH` (абсолютный путь к JKS вне репозитория), `TRACHU_KEYSTORE_PASSWORD`, `TRACHU_KEY_ALIAS`, `TRACHU_KEY_PASSWORD`. Вводите секреты через защищённый ввод, не вставляйте их в команды, журналы, чат, GitHub Variables или исходники. Gradle не принимает неполную конфигурацию.
3. В Android Studio (с установленным Android SDK 36 и JDK 17) настройте доступ к Gradle 8.13. В репозитории **нет Gradle wrapper** (`gradlew`), поэтому команда `gradle` ниже работает только при наличии установленного Gradle 8.13 в `PATH`; в противном случае используйте встроенную сборку Android Studio. Из корня проекта выполните `gradle --no-daemon --no-configuration-cache assembleRelease bundleRelease`. Для монетизации дополнительно настройте собственный ID по [ADS.md](ADS.md). Без него релиз остаётся без коммерческих показов.
4. Проверьте `apksigner verify --verbose --print-certs app/build/outputs/apk/release/app-release.apk` для APK и `jarsigner -verify -verbose -certs app/build/outputs/bundle/release/app-release.aab` для AAB. Эти команды используют Android SDK Build Tools и JDK соответственно; при необходимости укажите полные пути к исполняемым файлам. Сравните SHA-256 сертификата с постоянным ключом, package `ru.epbloger.trachu`, versionCode и target SDK. Для проверки сертификата самого хранилища используйте `keytool -list -v -keystore <ПУТЬ_К_JKS> -alias <ВАШ_ALIAS>`. APK и AAB находятся в `app/build/outputs/apk/release/` и `app/build/outputs/bundle/release/`; если имя файла отличается, подставьте фактическое имя.
5. Проверьте установку и обновление предыдущего подписанного релиза с сохранением данных на устройстве, сохраните контрольные суммы и commit. Перед загрузкой удалите переменные с паролями из окружения. Не меняйте ключ для обычного обновления, увеличивайте versionCode после первой публикации.

Не добавляйте ключ, пароль или секреты подписи в публичную CI-конфигурацию. В настоящий момент ключ владельца не предоставлен; инструкции и условная конфигурация не означают, что подпись уже выполнена.

## Подписание готовых артефактов CI без повторной сборки

Если параметры готового release уже соответствуют планируемой публикации (в частности, рекламный ID и флаг), можно подписать именно проверенный APK/AAB, не устанавливая Gradle и полный SDK. Скачайте unsigned release APK и/или AAB из одного Android integration, прошедшего все обязательные проверки приложения; для `55a0d20` см. [объяснение статуса и повторную проверку доказательств](QA_REPORT.md). Распакуйте с сохранением структуры каталогов в одну папку вне репозитория. Не используйте debug APK. Скрипт `store/rustore/sign-release.ps1` проверяет полный SHA исходников и SHA-256 каждого присутствующего release-файла из `qa/SHA256SUMS` до подписи. APK требует только Android SDK Build Tools 35.0.0 или новее, AAB — JDK с jarsigner. Пример PowerShell (замените параметры своими фактическими путями и полным SHA из проверенного CI):

```powershell
& .\store\rustore\sign-release.ps1 -ArtifactDir 'D:\release-input' -ExpectedCommit '<40-символьный SHA>' -VerifyOnly
& .\store\rustore\sign-release.ps1 -ArtifactDir 'D:\release-input' -ExpectedCommit '<40-символьный SHA>' -Keystore 'D:\private\trachu.jks' -KeyAlias '<alias>' -BuildToolsDir '<путь к build-tools\35.0.0>' -OutputDir 'D:\trachu-signed'
```

Для AAB без APK параметр `BuildToolsDir` не нужен. Пароли вводятся интерактивно утилитами подписи. Не передавайте их в чат или командную строку. Скрипт не генерирует ключ, не меняет исходные файлы, не пересобирает приложение и не отправляет файлы в магазин. Он сохраняет подписанные файлы в новой папке и формирует `SIGNED-SHA256SUMS.txt`; сравните сертификат с постоянным ключом и проверьте установку. При ошибке не публикуйте частичные результаты. Если нужно изменить рекламу, сначала соберите и проверьте новый release с собственным ID: подпись сама по себе не меняет настройки рекламы.

## Проверка перед отправкой в RuStore

- В PowerShell после успешной сборки получите контрольные суммы командой `Get-FileHash -Algorithm SHA256 app/build/outputs/apk/release/app-release.apk` (аналогично для AAB). Сохраните SHA-256 файла, отпечаток сертификата, `versionCode`, `versionName` и полный SHA Git-коммита в журнал выпуска без паролей. Удалите секретные переменные из текущего сеанса командой `Remove-Item Env:\TRACHU_KEYSTORE_PASSWORD,Env:\TRACHU_KEY_PASSWORD -ErrorAction SilentlyContinue` и закройте терминал.
- Для первой загрузки APK в RuStore достаточно подписанного APK; при загрузке AAB RuStore дополнительно запрашивает настройку ключей подписи в консоли. Если приложение уже распространялось в другом магазине, заранее согласуйте сертификаты: иначе межмагазинные обновления могут не установиться. [Официальная инструкция RuStore](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication/apk-signature).
- Перед выпуском проверьте, что установка **поверх** предыдущей версии с тем же сертификатом сохраняет локальную базу и чеки. Переустановка с удалением приложения эту гарантию не проверяет.
