# Архитектура и финансовые инварианты

## Слои

- `core`: Kotlin-модели, Money, Finance; без Android-зависимостей, единая бизнес-логика.
- `data`: Room, транзакционный LedgerStore, CSV, AES-GCM backup, курсы ЦБ, PDF.
- `security`: DataStore и Keystore для защищённого PIN-верификатора.
- `AppViewModel`: наблюдение за Room, последовательные действия, обработка ошибок.
- `ui`: Material 3, навигация, адаптивные экраны и формы.
- `worker`: WorkManager для повторений и уведомлений; `widget`: Glance.

Room хранит независимые типизированные записи в ledger_records с составным первичным ключом (kind,id), JSON-полем и версией формата. Отдельные записи для счетов, категорий, операций, планов, бюджетов, целей, долгов, курсов и чеков. Распределения и исторические курсы — поля операции; чеки разбиты на сегменты по 24 000 символов для ограничений SQLite CursorWindow. В отличие от хранения одной огромной JSON-строки, меняются только отличающиеся строки. Связность и денежные инварианты проверяет доменное ядро до записи; вся мутация и удаление происходят в Room withTransaction. Чтение наблюдает согласованный снимок таблицы. Деструктивный fallback запрещён.

Схема 2 добавляет formatVersion к схеме 1, миграция сохраняет все строки. Для будущих изменений — явная миграция Room, версия формата payload, совместимый декодер и тест открытия старой базы. Экспорт схемы включён через kapt, CI сохраняет результат.

## Деньги

- Long в минимальных денежных единицах каждой ISO-валюты. Точка/запятая разбирается BigDecimal, лишние дробные знаки отвергаются. Никакого Double в расчётах денежных сумм; Double используется только для пропорций графиков. Проверяемое сложение/вычитание, округление HALF_EVEN только на границе валютного пересчёта.
- Основная валюта выбирается до начала учёта и фиксируется. Операция хранит исходную сумму, точный курс и пересчитанную сумму отчёта. Новый курс не переписывает историю; общий баланс пересчитывается на дату просмотра по последнему доступному курсу. При отсутствии курса сумма этой валюты не включается в сводку и отображается предупреждение.
- Баланс = начальный остаток + проведённые движения. Перевод — одна запись с двумя счетами и двумя положительными суммами; обе стороны учитываются атомарно, отчёты доход/расход его исключают. Межвалютный перевод хранит фактически полученную сумму.
- Расход/доход: распределения по категориям в сумме точно равны исходной и пересчитанной суммам. Кумулятивное округление гарантирует отсутствие потерянных копеек.
- Возврат: запись с originalId, тем же счётом и историческим курсом покупки; уменьшает расходы на дату возврата. Общая сумма возвратов ограничена исходной покупкой. Возврат распределяется последовательно по оставшимся частям, полный возврат точно закрывает остаток. Покупка со связанными возвратами защищена от изменения/удаления до удаления возвратов.
- Долг: можно записать существующую задолженность или движение при получении/выдаче. Основной долг исключён из доходов/расходов; фактически уплаченные проценты отражаются отдельно. Ставка — ориентир для оценки простых процентов, не банковский график амортизации. Остаток долга не может стать отрицательным.
- Цели: виртуальное резервирование денег; начальная сумма и история пополнений/снятий. Это не новое движение счёта, поэтому нет двойного учёта.
- Бюджеты: календарный месяц, расход минус возвраты, категория включает её подкатегории. Переносится положительный остаток; превышение определяется точным сравнением сумм, а не округлённым процентом. Пользовательское начало отчётного месяца влияет на обзор и отчёты, не на календарные бюджеты.
- Плановые операции не меняют фактический баланс. Повторения имеют стабильный UUID из расписания и даты, атомарно записываются с продвижением nextDay; повторный запуск не дублирует. Фоновое выполнение приблизительное (ограничения Android); ручное подтверждение в дату операции. Для нового повторения используется доступный исторический курс, иначе сохранённый курс шаблона.
- Прогноз на 30 дней создаётся в памяти, не записывает операции. Не является гарантией будущего баланса.

## Данные и безопасность

Пользователь сам выбирает файл через Storage Access Framework. Backup — версионированный контейнер, PBKDF2-HMAC-SHA256 (310 000 итераций), случайные salt/IV, AES-256-GCM с аутентификацией заголовка. Перед заменой данных проверяются пароль, тег, формат и инварианты. Восстановление заменяет снимок целиком, не добавляет его поверх; PIN, тема и системные настройки не переносятся. Лимит входного файла 100 МиБ; большие фото повышают расход памяти.

CSV ТРАЧУ. содержит все связанные записи и читаемые колонки. Идентичные записи с тем же ID не дублируются; конфликт отклоняет импорт целиком. Формат выписки: date,amount,category,note,id; дата ISO, сумма со знаком в валюте выбранного счёта. Без внешнего ID используется идентификатор содержания и номера одинакового вхождения: надёжно для повторного импорта одинакового файла, не универсальная банковская дедупликация произвольных перекрывающихся выписок. CSV/PDF не зашифрованы.

PIN: salted PBKDF2-верификатор хранится зашифрованным ключом Android Keystore, лимит попыток и авто-блокировка. PIN не является полнодисковым шифрованием Room; действует изоляция Android. Биометрия через BiometricPrompt, сильная биометрия, опционально. При PIN виджет не показывает баланс, защищено окно. Системное резервное копирование отключено. Сеть: только HTTPS к cbr.ru по ручной команде или отдельно включённому суточному обновлению, без передачи сумм/истории; ручные курсы не перезаписываются опубликованными. Никаких аналитических SDK, рекламы и банковских аккаунтов.

## Сборка

AGP 8.13.2, Gradle 8.13, Kotlin 2.2.21, JDK 17, compile/target 36, min 26. Пинованные версии зависимостей. [Совместимость AGP](https://developer.android.com/build/releases/agp-8-13-0-release-notes), [AndroidX stable](https://developer.android.com/jetpack/androidx/versions/stable-channel). CI выполняет сборку, тесты, lint, Android instrumentation; APK/AAB создаются крупным интеграционным циклом. Release AAB требует отдельного ключа публикации.
