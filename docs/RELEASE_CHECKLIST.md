# Проверка готовности

Для 1.2.0 обязательны все прежние проверки, новый UX, обе реальные миграции с 1.0.0 и принятой 1.1.0, проверка системного разрешения уведомлений, отдельные PNG целей и долгов, полный Android integration на окончательном SHA main. Проверенная версия, точные результаты и хеши указываются в описании соответствующего GitHub Release. До этого APK 1.2.0 не считается принятым.

Публикация тестового APK запускается только после визуальной приёмки оригинальных PNG, проверки безопасной QA-выборки и полного успешного Android integration на текущем `main`. Аннотированный тег `v1.2.0-debug` с номером принятого прогона и SHA-256 его QA-архива запускает отдельный workflow `publish-debug.yml`. Он повторно сверяет SHA и успешные этапы CI, артефакты и debug-сертификат, проверяет unsigned APK/AAB через VerifyOnly, создаёт черновик с исходным APK и ограниченным набором QA, сверяет загруженные файлы и после публикации скачивает их по публичным ссылкам. До ручной приёмки тег создавать нельзя. Это не подпись издателя и не публикация в RuStore.

## Историческая основа 1.1.0

Android-код 1.1.0 ([09aabc3](https://github.com/epbloger/trachu/commit/09aabc3cf14f381db30d166464740ff880f91908)) прошёл 154/154 в [CI #45847845826](https://github.com/epbloger/trachu/actions/runs/45847845826): телефон/планшет, API26/33/36, реальные обновления обеих baseline, SQLite 4250 после холодного офлайн-перезапуска, Lint без ошибок, статические 16 КиБ. Итоговый SHA и контрольные суммы передаваемого debug APK — в [тестовом релизе](https://github.com/epbloger/trachu/releases); результаты и границы проверки — в [QA_REPORT.md](QA_REPORT.md). Постоянный ключ, физические проверки и публикация RuStore остаются отдельными этапами.

Ограничения первой версии: без облачной синхронизации, без подключения банков; баннерная реклама опциональна и по умолчанию в release отключена; ручные курсы и отключаемое автоматическое обновление ЦБ РФ; приблизительное время фонового запуска; простой ориентир процентов вместо амортизационного графика; CSV вместо нативного XLSX, файл открывается в Excel; основная валюта фиксируется после начала учёта. До подтверждения всех аппаратных сценариев и подписи называть результат кандидатом, а не финальным опубликованным релизом.

## Финальная приёмка владельцем

1. Выбрать выпуск без рекламы (имеющийся проверенный release) либо настроить собственный блок РСЯ для `ru.epbloger.trachu`, собрать и проверить вариант с ним по [ADS.md](ADS.md). Не переносить ID другого продукта. Сверить сетевую активность и декларации фактического варианта.
2. Сохранить APK/AAB и QA-архив из указанного прогона. Подписать постоянным ключом по [SIGNING.md](SIGNING.md); проверить сертификат и контрольные суммы. Секреты не передавать в репозиторий или чат.
3. Выполнить [ручную приёмку](MANUAL_ACCEPTANCE.md) на физическом устройстве, включая системный выбор файлов, биометрию, виджеты, уведомления и сетевые запросы. Сверить окончательные скриншоты с подписанной версией.
4. Заполнить реальные сведения издателя, возрастную категорию и декларации, загрузить подписанный файл и материалы согласно [STORE_PUBLICATION.md](STORE_PUBLICATION.md), отправить на модерацию.
