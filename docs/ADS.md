# Реклама Яндекса в ТРАЧУ.

Yandex Mobile Ads SDK 8.7.0 подключён как зависимость вместе с Compose-расширением. В отличие от приложения «ЗАБЕРИ.», здесь собственные параметры ТРАЧУ. Идентификаторы рекламных блоков других приложений в репозитории отсутствуют.

## Тестирование и релиз

- **Debug:** только официальный тестовый блок demo-banner-yandex. Он предназначен для проверки и не приносит рекламный доход.
- **Release:** реклама выключена по умолчанию: trachuAdsEnabled=false, идентификатор пуст. Без собственного рекламного блока SDK не инициализируется и запросы за рекламой не отправляются.
- **Release с рекламой:** передайте Gradle-параметры -PtrachuAdsEnabled=true и -PtrachuBannerId=R-M-<ID_ПРИЛОЖЕНИЯ>-<ID_БЛОКА> со значениями из собственного аккаунта РСЯ для ТРАЧУ. Если включить рекламу без ID или передать ID неправильного формата, Gradle-конфигурация завершится ошибкой.
- **GitHub Actions:** переменные репозитория TRACHU_ADS_ENABLED=true и TRACHU_BANNER_ID с собственным идентификатором маппятся на эти Gradle-параметры. Изменение переменных применяется в следующем ручном или обычном запуске Android integration. Debug по-прежнему использует только демонстрационный ID.
- Отключение SDK в release реализовано через BuildConfig.YANDEX_BANNER_ID (пустое значение) и запрет автоматической инициализации в AndroidManifest.xml. SDK остаётся зависимостью проекта. Правило manifest merger удаляет рекламный идентификатор AD_ID.

Интеграция SDK: https://ads.yandex.com/helpcenter/ru/dev/android/quick-start

Compose sticky-баннер: https://ads.yandex.com/helpcenter/ru/dev/android/compose/adaptive-sticky-banner

## Размещение и приватность

Баннер отображается только на вкладке «Обзор» после разблокировки, под содержимым обзора и над нижней навигацией. Он исчезает при открытии редактора, деталей операции, быстрого ввода либо при блокировке. На широких экранах баннер ограничен по ширине. Полноэкранной рекламы нет.

SDK запускается один раз при первом посещении обзора и только при наличии ID. Перед запуском передаются setUserConsent(false) и setLocationTracking(false). Приложение не определяет возраст пользователя: age-restricted-статус нельзя произвольно устанавливать для всех взрослых. При выпуске для несовершеннолетней аудитории требуется отдельная проверка возрастных и рекламных правил.

Рекламный ID Android исключён. Финансовые операции, категории, счёта, PIN, чеки и суммы не передаются приложением в рекламные запросы. Яндекс может самостоятельно обрабатывать сетевую и техническую информацию, информацию об устройстве, запросах и показах в соответствии со своей политикой https://yandex.ru/legal/confidential/.

Перед выпуском сборки с рекламой необходимо проверить фактический сетевой трафик, декларации магазинов и опубликованную политику. Две копии политики (docs/PRIVACY_POLICY.md и app/src/main/assets/legal/privacy.txt) должны совпадать.

## Что проверить перед публикацией

1. В settings.gradle.kts внутри dependencyResolutionManagement подключён https://ads.maven.yandex.net/ с content-фильтрами includeGroup("com.yandex.android") и includeGroupAndSubgroups("com.yandex.ads").
2. В debug на «Обзоре» отображается официальный тестовый блок. После перехода на операции, план, экран PIN или в редактор баннер отсутствует.
3. В release без флага нет инициализации Yandex Ads. При включении release проверьте, что используется только собственный ID из РСЯ.
4. На устройствах API 26+ и при повороте/крупном шрифте баннер не закрывает функции. Проверить merged manifest, разрешения, отсутствие AD_ID, Logcat (YandexAds) и сетевые запросы.
5. Если реклама включена, обновить анкету «Содержит рекламу», декларации обработки данных и публичные юридические документы. Демоблок нельзя публиковать.
