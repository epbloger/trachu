# Публикация в RuStore и Google Play

## Карточка

Название: ТРАЧУ. — личные финансы

Краткое описание: Доходы, расходы, бюджеты, счета, долги и цели. Без регистрации.

Полное описание: Управляйте личными финансами в одном приложении. Создавайте счета, записывайте доходы и расходы, переводите деньги между счетами, отслеживайте бюджет, возвращайте покупки и планируйте платежи. Изучайте графики и сравнивайте периоды. Ведите долги и накопительные цели, сохраняйте чеки и выбирайте валюты. Настройте PIN и биометрию, сохраняйте зашифрованную резервную копию, экспортируйте таблицы и PDF. Основные функции работают без интернета. Без банковских подключений и регистрации. В сборке с включённой рекламой на обзоре может отображаться небольшой баннер.

Категория: Финансы / личные финансы. Возрастную анкету заполнять по реальному содержимому. Никаких платежей или финансового консультирования. Приложение не является банковским приложением.

Package: ru.epbloger.trachu. Min Android 8, target API 36.

## Декларации данных

Операции, счета, чеки, теги, долги, цели и PIN хранятся локально. Не заявлять абсолютное отсутствие любой сетевой обработки: публичный запрос курсов к ЦБ РФ раскрывает обычные технические сведения сервера/сети. Приложение включает Yandex Mobile Ads SDK с ручной инициализацией: release без ID и флага рекламы сетевых запросов рекламы не делает; в сборке с рекламой SDK может обрабатывать техническую информацию и сведения о показах, даже при отсутствии согласия на персонализацию. При заполнении Google Play Data safety и RuStore проверить актуальные определения сбора/передачи, политику Яндекса, фактический merged manifest и сетевой трафик: один лишь выключенный баннер не доказывает отсутствия собираемых SDK данных. Отдельный файл CSV/PDF/backup создаётся пользователем через SAF; учётной записи нет, удаление аккаунта не требуется.

## Перед выпуском

1. Успешные проверки, установка APK на устройства и тестирование резервного восстановления, PIN/биометрии, виджетов, разрешений, валютного запроса и масштабирования.
2. Сформировать и сохранить release signing key вне репозитория; загрузить подписанный AAB/APK согласно требованиям магазина. Не использовать debug key для публикации.
3. Снять настоящие скриншоты смартфона и планшета на релизном интерфейсе с отдельным тестовым набором данных, подготовить иконку/баннер. Не выдавать дизайн-мокапы за скриншоты.
4. Проверить актуальные требования: [RuStore](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/requirement-apps), [Google Play target API](https://developer.android.com/google/play/requirements/target-sdk), [Google Play Data safety](https://support.google.com/googleplay/android-developer/answer/10787469).
5. Владелец заполняет действительные реквизиты аккаунта, декларации, проверку издателя и подтверждает публикацию. Никаких вымышленных регистрационных сведений.
6. Если показывается реклама, указываются собственный идентификатор рекламного блока и параметр включения из docs/ADS.md; тестовый блок недопустим в release. Обновить публичную политику, отметку «Содержит рекламу» и декларации персональных данных. Проверить, что финансовые формы и PIN не содержат объявлений.
