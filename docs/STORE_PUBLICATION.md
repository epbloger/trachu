# Публикация в RuStore и Google Play

## Карточка

Название: ТРАЧУ. — личные финансы

Краткое описание: Доходы, расходы, бюджеты, счета, долги и цели. Без регистрации.

Полное описание: Управляйте личными финансами в одном приложении. Создавайте счета, записывайте доходы и расходы, переводите деньги между счетами, отслеживайте бюджет, возвращайте покупки и планируйте платежи. Изучайте графики и сравнивайте периоды. Ведите долги и накопительные цели, сохраняйте чеки и выбирайте валюты. Настройте PIN и биометрию, сохраняйте зашифрованную резервную копию, экспортируйте таблицы и PDF. Основные функции работают без интернета. Без рекламы, банковских подключений и регистрации.

Категория: Финансы / личные финансы. Возрастную анкету заполнять по реальному содержимому. Никаких платежей или финансового консультирования. Приложение не является банковским приложением.

Package: ru.epbloger.trachu. Min Android 8, target API 36.

## Декларации данных

Операции, счета, чеки, теги, долги, цели и PIN хранятся локально. Не заявлять абсолютное отсутствие любой сетевой обработки: публичный запрос курсов к ЦБ РФ раскрывает обычные технические сведения сервера/сети. При заполнении Google Play Data safety и RuStore проверить актуальные определения сбора/передачи и фактический merged manifest. Отдельный файл CSV/PDF/backup создаётся пользователем через SAF. Сторонних рекламных/аналитических SDK нет; учётной записи нет, удаление аккаунта не требуется. Проверить форму финансовых функций и применимость деклараций по правилам конкретного магазина.

- Политика: https://github.com/epbloger/trachu/blob/main/docs/PRIVACY_POLICY.md
- Условия: https://github.com/epbloger/trachu/blob/main/docs/TERMS.md
- Поддержка: helpmoorkis@yandex.ru

Публичные документы должны быть доступны без входа. Перед публикацией рекомендуется официальный статический сайт с постоянными URL и сведениями фактического издателя.

## Перед выпуском

1. Успешные проверки, установка APK на устройства и тестирование резервного восстановления, PIN/биометрии, виджетов, разрешений, валютного запроса и масштабирования.
2. Сформировать и сохранить release signing key вне репозитория; загрузить подписанный AAB/APK согласно требованиям магазина. Не использовать debug key для публикации.
3. Снять настоящие скриншоты смартфона и планшета на релизном интерфейсе с отдельным тестовым набором данных, подготовить иконку/баннер. Не выдавать дизайн-мокапы за скриншоты.
4. Проверить актуальные требования: [RuStore](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/requirement-apps), [Google Play target API](https://developer.android.com/google/play/requirements/target-sdk), [Google Play Data safety](https://support.google.com/googleplay/android-developer/answer/10787469).
5. Владелец заполняет действительные реквизиты аккаунта, декларации, проверку издателя и подтверждает публикацию. Никаких вымышленных регистрационных сведений.
