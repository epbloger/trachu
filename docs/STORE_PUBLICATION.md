# Публикация ТРАЧУ. в RuStore

Состояние на 26.11.2026: тексты карточки подготовлены, растровая иконка готова; выпуск **не отправлен**. Обязательные реальные скриншоты, окончательный подписанный APK/AAB, данные издателя и декларация фактической релизной сборки пока требуют проверки. Для публикации в других магазинах условия и анкеты проверяются отдельно.

## Карточка

Название: ТРАЧУ. — личные финансы

Краткое описание: Доходы, расходы, бюджеты, счета, долги и цели. Без регистрации.

Полное описание: Управляйте личными финансами в одном приложении. Создавайте счета, записывайте доходы и расходы, переводите деньги между счетами, отслеживайте бюджет, возвращайте покупки и планируйте платежи. Изучайте графики и сравнивайте периоды. Ведите долги и накопительные цели, сохраняйте чеки и выбирайте валюты. Настройте PIN и биометрию, сохраняйте зашифрованную резервную копию, экспортируйте таблицы и PDF. Основные функции работают без интернета. Без банковских подключений и регистрации. В сборке с включённой рекламой на обзоре может отображаться небольшой баннер.

Тип: неигровое приложение. Основная категория: **Финансы** (RuStore прямо относит сюда сервисы учёта расходов и бюджета). Дополнительная категория не требуется. Возрастную категорию выбрать по фактическому содержимому, включая рекламу, если она включена. Никаких платежей или финансового консультирования. Приложение не является банковским приложением.

Package: ru.epbloger.trachu. Min Android 8, target API 36.

## Декларации данных

Операции, счета, чеки, теги, долги, цели и PIN хранятся локально. Не заявлять абсолютное отсутствие любой сетевой обработки: публичный запрос курсов к ЦБ РФ раскрывает обычные технические сведения сервера/сети. Приложение включает Yandex Mobile Ads SDK с ручной инициализацией: release без ID и флага рекламы сетевых запросов рекламы не делает; в сборке с рекламой SDK может обрабатывать техническую информацию и сведения о показах, даже при отсутствии согласия на персонализацию. При заполнении Google Play Data safety и RuStore проверить актуальные определения сбора/передачи, политику Яндекса, фактический merged manifest и сетевой трафик: один лишь выключенный баннер не доказывает отсутствия собираемых SDK данных. Отдельный файл CSV/PDF/backup создаётся пользователем через SAF; учётной записи нет, удаление аккаунта не требуется.

## Графические материалы

- **Готова иконка RuStore:** `store/rustore/trachu-icon-512.png` — 512×512 PNG, непрозрачная, с теми же цветами, формой буквы и точкой, что Android `ic_launcher.xml`. Размер должен быть не более 3 МБ; при любом изменении иконки APK пересоздайте картинку для магазина вместе с ней. В `site/assets/icon.svg` скруглённые углы, поэтому его не используем в качестве иконки RuStore: установленная Android-иконка имеет сплошной квадратный фон.
- **Скриншоты телефона обязательны:** минимум **3** разных настоящих снимка экрана приложения (для выбранной ориентации), можно загрузить до 10 за раз. Подготовьте 3–5 кадров из **той же подписанной release-сборки**, что предназначена для RuStore, в одной вертикальной ориентации, с вымышленными данными и без системной строки состояния, сторонней рекламы и экрана PIN. Рекомендуется высокое исходное разрешение, при этом официальный максимум — 2160×3840, размер файла — до 3 МБ, формат PNG/JPG. Показать, например: обзор; список операций с фильтрами; бюджеты/цели; аналитику; настройки защиты.
- **Скриншоты планшета необязательны:** при их загрузке нужно **от 3** настоящих кадров в единой горизонтальной ориентации; размер файла до 5 МБ. Иначе карточка на планшете использует телефонные снимки. Для TV-версии скриншоты/баннер не готовить: ТРАЧУ. выпускается для телефона и планшета.
- Имеющиеся `site/assets/screens/phone-dashboard.png` и `phone-operations.png` — только **два** кадра 320×640; `tablet-analytics.png` — **один** 1280×800. Они иллюстрируют сайт, но **не выполняют минимальное требование RuStore**. Не растягивайте их и не подменяйте реальные кадры дизайн-макетами.
- Автоматические снимки интерфейса, которые CI может формировать в **debug** на эмуляторе (в том числе 1080×2400), подходят для проверки качества и предварительного отбора экранов. Debug-пакет использует тестовую подпись и демонстрационную рекламу. Финальные изображения для публикации необходимо проверить на **подписанном издателем release APK** и выполнить ручную проверку на реальном устройстве: автоматический кадр не подтверждает работу production-сборки.

Официальные ограничения: [публикация приложения](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication), [правила для иконок/скриншотов](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/requirement-apps).

## Что указать в консоли

1. Добавить приложение может владелец аккаунта. Название — до 30 символов, краткое описание — до 80, полное — до 4000; первые 2000 должны содержать главное. Основная категория — «Финансы», дополнительную оставить пустой, если нет оснований для неё. Возрастной рейтинг выбрать по фактической сборке. Поисковые теги — до 5, необязательны.
2. Сведения о разработчике: адрес поддержки и сайт указаны выше. Юридические реквизиты и статус издателя вводит владелец аккаунта на основании реальных документов, без публичной подстановки вымышленных данных.
3. В разделе безопасности данных проверить все типы информации, которые передаются **приложением и любым SDK**: IP/сетевые и технические сведения при обращении к ЦБ, а для версии с рекламой — категории данных, предусмотренные фактической версией Yandex SDK, на основании его документации и трафика. Счета и финансовые записи сами по себе остаются локальными. Указать назначение `INTERNET` (курсы/при включённой рекламе баннеры), `POST_NOTIFICATIONS` (напоминания по разрешению), `USE_BIOMETRIC` (PIN/биометрия) и технические разрешения из итогового APK. Нельзя автоматически отмечать «никакие данные не передаются» только потому, что нет собственного сервера.
4. Если в **публикуемом** APK отображается коммерческий баннер, указать наличие рекламы и проверить отдельное добровольное согласие/отказ/отзыв; если рекламный ID пуст и баннер выключен, декларировать поведение именно этой сборки. В любом случае проверить итоговый `merged manifest`, разрешения и сетевой трафик.
5. Для первой версии загрузить **подписанный постоянным ключом** APK либо AAB и настоящие скриншоты. RuStore принимает APK/AAB до 5 ГБ. Для AAB сперва настройте сертификат подписи в консоли по инструкции RuStore; для следующих версий требуется тот же package, совместимый сертификат и возросший `versionCode`. Файлы после загрузки обрабатываются, а неотправленные на модерацию обработанные файлы удаляются через 14 дней.

## Перед выпуском

1. Успешные проверки, установка APK на устройства и тестирование резервного восстановления, PIN/биометрии, виджетов, разрешений, валютного запроса и масштабирования.
2. Сформировать и сохранить постоянный release signing key вне репозитория; выполнить [инструкцию подписи](SIGNING.md). Не использовать debug key для публикации.
3. Снять минимум три настоящих скриншота смартфона на релизном интерфейсе с отдельным тестовым набором данных. Иконка 512×512 уже подготовлена, остальные материалы проверять по разделу выше. Не выдавать дизайн-мокапы за скриншоты.
4. Проверить актуальные требования: [RuStore](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/requirement-apps), [Google Play target API](https://developer.android.com/google/play/requirements/target-sdk), [Google Play Data safety](https://support.google.com/googleplay/android-developer/answer/10787469).
5. Владелец заполняет действительные реквизиты аккаунта, декларации, проверку издателя и подтверждает публикацию. Никаких вымышленных регистрационных сведений.
6. Если показывается реклама, указываются собственный идентификатор рекламного блока и параметр включения из docs/ADS.md; тестовый блок недопустим в release. Обновить публичную политику, отметку «Содержит рекламу» и декларации персональных данных. Проверить, что финансовые формы и PIN не содержат объявлений.
